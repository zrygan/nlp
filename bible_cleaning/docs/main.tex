App) was used as the source of biblical text. To ensure a sufficiently large
corpus for each language, we set the minimum corpus size (\( |C| \)) to be
50,000 tokens. the complete English Bible contains approximately 760,000 words,
this threshold is suitable because some translations are incomplete or still in
progress~\cite{JJS11}. Examples of unfinished translations include those for

\subsection{Web Scraping and Parsing}

YouVersion serves each chapter as an HTML document, so extraction reduces to
identifying the markup that carries translated text and discarding everything
else. A manual scan of the source revealed a stable convention: every span whose
class is prefixed with \texttt{ChapterContent\_verse\_\_} encloses exactly one
verse, and within it the verse number and the verse text are carried by spans
prefixed with \texttt{ChapterContent\_label\_\_} and
\texttt{ChapterContent\_content\_\_} respectively.
\Cref{list:chapter_content} shows the markup for Gen 1:1.

\begin{lstlisting}[language=HTML, caption={\texttt{ChapterContent\_verse\_\_} tag}, label={list:chapter_content}]
<span 
    data-usfm="GEN.1.1"
    class="ChapterContent_verse__57FIw">
    
    <span class="ChapterContent_label__R2PLt">
        1
    </span>
    
    <span class="ChapterContent_content__RrUqA">
        Nang pasimula, nilikha ng Diyos ang
        langit
    </span>
    
    <span class="ChapterContent_note__YlDW0">
        <!-- content note -->
    </span>
    
    <span class="ChapterContent_content__RrUqA">
        at ang lupa.
    </span>
</span>
\end{lstlisting}

The notation we will use to refer to a specific biblical chapter and a verse is
\[\texttt{ChapterShorthand ChapterNumber:VerseNumber}\]
For example, the above chapter and verse in the above listing will be referred
to as Gen 1:1. For a range of verses we will instead use
\[\texttt{ChapterShorthand ChapterNumber:RangeStart-RangeEnd}\]
For example, we will use Gen 1:1-3 to refer to the first three verses of
Genesis chapter 1.

Two properties of this structure determine the extraction rule. First, a verse is
not necessarily contained in a single \texttt{content} span. In
\cref{list:chapter_content} the verse is split across two of them, and the text
is recovered only by concatenating them in document order. Second, editorial
apparatus supplied by YouVersion rather than by the translators, such as
footnotes and cross-references, occupies \texttt{ChapterContent\_note\_\_} spans
interleaved with the text. Taking every descendant string of a verse span would
therefore splice editorial content into the middle of the verse it annotates. We
consequently retain only the \texttt{content} descendants, concatenate them in
document order, and discard every sibling class, so that the corpus contains the
translated text alone.

Scraping and parsing are fused into a single pass. The crawler registers a
handler on the verse selector and cleaning is applied to each match as it is
encountered, so no intermediate copy of the markup is retained. The
implementation uses the Colly framework for Go. Cleaning is a sequence of
regular expression substitutions, enumerated in~\cref{tab:regex}, which
restrict the character set to letters, digits, whitespace, and basic
punctuation, and strip the residual verse numbering contributed by the label
spans.

\begin{table}[h!]
    \centering
    \begin{tabular}{p{\dimexpr0.5\linewidth\relax} p{\dimexpr0.4\linewidth\relax}}
        \hline
        \textbf{Regular Expression (RE)}        & \textbf{Purpose}                                                                      \\
        \hline
        \verb|[^a-zA-Z0-9\s\.\,\;\:\!\?\'\"-]+| & Remove all characters that are not letters, digits, whitespace, or basic punctuation. \\
        \verb|[:\s]+$|                          & Match one or more colons or spaces at the end of a line.                              \\
        \verb|^[\d#:\s]+|                       & Remove leading numbers, hashes, colons, or spaces at the start of a line.             \\
        \hline
    \end{tabular}
    \caption{REs used for text cleaning}\label{tab:regex}
\end{table}

Traversal exploits the same principle as extraction. Every chapter page carries
a navigation anchor to its successor, which is distinguishable from the other
links into \texttt{/bible/} by its accessible title of ``Next Chapter''. The
crawler resolves this anchor and follows it, so a translation is walked as a
linear chain from its seed chapter rather than as a general crawl of the site. A
hash set of visited URLs guarantees termination, which matters because the final
chapter of a translation links back into the same book rather than to nothing.
Because each chain is sequential, parallelism is available only across
languages, and each of the sixteen translations was therefore collected in its
own concurrent stream.

The class names in \cref{list:chapter_content} carry a build-specific suffix,
such as \texttt{\_\_57FIw}, that changes whenever YouVersion redeploys its front
end. Matching on the stable prefix rather than the full class name is what makes
the scraper robust to those redeployments, though a change to the underlying
convention would still require the manual scan to be repeated.

\section{Segmenting the Corpus}

\subsection{Verse Segmenting}
The verse segmenting is done during the web scraping step. Each verse has
regular expressions applied in order to clean the text. The regular expressions
used are enumerated in~\cref{tab:regex}.

\subsection{Sentence Segmenting}
The sentence segmenting takes the existing verse segmentation after being web
scraped and further segments it into sentences by using a regular expression
that matches sentence-ending punctuation marks such as periods, exclamation
marks, and question marks. Cases such as titles were accounted for this in this
regular expression in order to avoid incorrect segmentation.

\section{Parallel Corpus}

\subsection{Indexing and Methodology}

Indexing was used in order to align the verses of each language. The index was
obtained by applying a RegEx on the each respective file in order to determine
the language prefix, the code for the book, the book name, and the verse
number. Through this, we were able to create a unique map that allows us to
align the verses of each language.\\

After which, we created a new file for each language that contains the verses
that are aligned with the other languages. This was done by iterating through
the index and checking if the verse exists in the respective language file. If
it does, we append it to the new file.\\
